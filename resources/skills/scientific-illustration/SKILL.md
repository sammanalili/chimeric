# Scientific illustration

Identify the concept, audience and relationships the reader must understand. Separate established structures and processes from hypotheses or unknown details. Use a schematic when the goal is to explain relationships; do not imply measured geometry or scale without evidence.

Use [the style guide](references/style-guide.md) for appearance. Read [illustration methods](references/illustration-methods.md) when choosing vector drawing or illustrative art, arranging a diagram, or reviewing an export. This skill has no required renderer, remote service or bundled asset dependency.

Keep labels, arrows, panel letters, scale information and quantitative marks separate and editable where possible. Prefer code, SVG or native document shapes for structural diagrams. Use illustrative raster art only when it improves the explanation and an appropriate capability is available. Follow the user's authorization and actual tool requirements for any external service.

Inspect scientific references and the resulting artwork. Do not create synthetic observations, source imaging or data panels. Label conceptual drawings and uncertain relationships clearly. Preserve the source and license of reused artwork, and disclose generated art when relevant to the deliverable.

Before delivery, check that every arrow, label and spatial relationship conveys the intended meaning, that no required step was removed to simplify the layout, and that the exported file remains readable. Deliver editable source with the requested output when feasible. State unresolved scientific or rendering limits plainly.
